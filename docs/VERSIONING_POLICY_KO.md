# Guardian 버전 정책

## 출시 전 버전

정식 출시 승인 전에는 모든 배포 구성요소를 사전 출시 버전으로 유지합니다. 각 앱·서비스는 독립 버전을 가질 수 있지만 정식 출시 여부를 혼동시키는 `1.0.0` 또는 `1.x` 표기를 사용하지 않습니다.

- 초기 개발: `0.1.0-dev`
- 개발 수정: `0.1.1-dev`, `0.2.0-dev`
- 베타: `0.9.0-beta.1`
- 출시 후보: `1.0.0-rc.1`
- 최초 정식 출시: 출시 승인 및 수용 검증 후에만 `1.0.0`

## 적용 범위

Android 앱, Windows 앱/설치 프로그램, 라이선스 발급기, 라이선스 API, 필터 배포 서비스는 각각의 패키지 버전과 설치/배포 메타데이터를 일치시켜야 합니다. Android의 단조 증가 versionCode와 개발 태그 번호는 업데이트 식별자일 뿐 정식 출시를 뜻하지 않습니다. Android 로컬 빌드 기본값과 CI 버전 계산기의 기준값은 마지막으로 확인된 개발 릴리스와 일치시켜, 오래된 fallback 값이 실제 앱 버전을 뒤로 되돌리지 않도록 합니다. Chrome 확장 프로그램의 `manifest.json` 버전은 Chrome 규격상 숫자 점 표기만 허용하므로 `0.x.y`를 유지하고, 사전 출시 여부는 확장 프로그램 배포 채널과 저장소 릴리스 상태로 구분합니다.

## 정식 출시 승인 기준

핵심 기능의 실제 환경 수용 테스트, 설치·실행·업데이트·제거 검증, 산출물 해시·서명·매니페스트 검증, 운영·보안·라이선스 준비 및 명시적 출시 승인이 모두 확인되기 전에는 정식 버전으로 승격하지 않습니다. CI 통과나 개발 APK 발행만으로 출시로 간주하지 않습니다.

## 라이선스 발급기 버전 기준

- Guardian License Manager는 `0.1.0-dev`에서 시작하며, 정식 출시 전에는 `0.x-dev` 버전을 유지합니다.
- 설치 프로그램 파일명, Inno Setup AppVersion, 앱 어셈블리 버전 및 화면 버전은 동일한 구성요소 릴리스 버전으로 맞춥니다.
- 정식 출시 승격 전 실제 발급 API 연결, 키 발급·검증·폐기, 허용 기기 수, 만료 처리, 운영 보안 및 실기기 설치 검증을 확인합니다.
