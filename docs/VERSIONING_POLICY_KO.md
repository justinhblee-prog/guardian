# Guardian 버전 정책

이 문서는 Guardian 제품군의 개발·베타·정식 출시 버전을 구분하기 위한 기준입니다.

## 기본 원칙

- 정식 출시 전 제품에는 `1.0.0` 이상의 정식 버전을 부여하지 않습니다.
- Android 앱, Windows 앱, 라이선스 발급기, 서버 API는 서로 독립된 배포 단위입니다. 각 구성요소의 버전은 해당 구성요소의 출시 단계만 나타내며, 다른 구성요소의 정식 출시를 의미하지 않습니다.
- Android의 `versionCode`, 빌드 번호, 개발 릴리스 태그(`guardian-dev-vN`)는 배포·업데이트 식별자입니다. 이 값이 증가해도 제품이 정식 출시된 것은 아닙니다.
- 설치 프로그램 파일명, MSI/Inno Setup의 AppVersion, 앱 어셈블리 버전 및 화면에 표시되는 버전은 같은 구성요소의 동일한 릴리스 버전을 사용해야 합니다.

## 버전 형식

| 단계 | 예시 | 의미 |
|---|---|---|
| 초기 개발 | `0.1.0-dev` | 기능 구현 및 내부 검증 |
| 개발 업데이트 | `0.1.1-dev`, `0.2.0-dev` | 개발 중 수정·기능 추가 |
| 베타 | `0.9.0-beta.1` | 외부 베타 검증 |
| 출시 후보 | `1.0.0-rc.1` | 정식 출시 후보, 최종 수용 테스트 |
| 최초 정식 출시 | `1.0.0` | 출시 승인 및 배포 준비가 완료된 경우에만 사용 |
| 정식 출시 후 | `1.1.0`, `1.0.1` | 기능 추가 또는 수정 |

## 정식 출시 버전 승인 조건

다음 항목이 확인되기 전에는 `1.0.0`으로 승격하지 않습니다.

1. 필수 기능이 실제 대상 환경에서 동작하고 차단·복구 등 핵심 흐름의 수용 테스트가 통과할 것.
2. Android/Windows 설치 패키지가 실제로 생성되고 설치·실행·업데이트·제거 검증을 통과할 것.
3. 릴리스 산출물의 SHA-256, 패키지 식별자, 서명 상태 및 업데이트 매니페스트가 검증될 것.
4. 개인정보·보안·라이선스·결제 등 출시 필수 운영 항목이 준비될 것.
5. 출시 승인자가 정식 출시를 명시적으로 승인할 것.

CI 성공, 개발 APK 발행, PR 병합, 빌드 번호 증가만으로 정식 출시로 간주하지 않습니다.

## 현재 적용

- Guardian License Manager: `0.1.0-dev`
- Guardian Android: 개발 릴리스 체계(`0.x-dev` 및 별도 단조 증가 개발 빌드 번호)
- Windows 및 서버 구성요소: 각 배포 단위의 개발 단계에 맞는 `0.x-dev` 체계

버전 변경은 해당 구성요소의 프로젝트 파일, 설치 프로그램 메타데이터, 릴리스 문서 및 자동화 설정에 일관되게 반영합니다.
