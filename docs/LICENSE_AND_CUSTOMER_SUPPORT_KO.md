# Guardian 라이선스 및 고객지원 운영 설계

> 갱신: 2026-11-20 (KST)
> 통합 브랜치: feature/android-support-center-mainline
> 주의: 이 문서는 구현 범위와 운영 한계를 정리합니다. 아직 실기기/운영 DB에서 검증되지 않은 항목을 완료로 간주하지 않습니다.

## 1. 라이선스 상품 및 기간

현재 API에서 지원하는 관리자 발급 상품은 다음과 같습니다.

| 상품 코드 | 기간 | 상태 |
|---|---:|---|
| short_7d | 7일 | 고정 기간 검증 구현 |
| monthly_30d | 30일 | 고정 기간 검증 구현 |
| quarterly_90d | 90일 | 고정 기간 검증 구현 |
| annual_365d | 365일 | 고정 기간 검증 구현 |
| custom | 1~36500일 | 관리자 직접 입력 |

관리자 화면에서 고정 상품을 선택하면 기간 입력은 잠깁니다. 서버도 planCode와 validDays를 별도로 검증하므로 고정 상품에 다른 기간을 전달하거나 지원하지 않는 상품 코드(예: Lifetime)를 보내면 거부합니다. 발급 이벤트에는 상품 코드, 기간, 기기 수 및 고객 연결 여부가 남습니다.

**아직 별도 구현이 필요한 항목:** 상품별 가격표, Google Play 또는 외부 결제 공급자, 서명된 결제 webhook, webhook 멱등 처리, 환불/차지백/취소 동기화, 7일 체험 중복 발급 방지, 자동 갱신 및 이메일 전달입니다. 관리자 수동 발급은 결제 완료 증거가 아닙니다.

Lifetime은 만료일 없는 entitlement와 refresh/정지/오프라인 검증의 의미가 구현되고 시험되기 전까지 발급하지 않습니다. 100년 등 임의의 장기 기간으로 영구 라이선스를 흉내 내지 않습니다.

## 2. 노트북/모바일 관리자 라이선스 발급 절차

관리자 페이지는 License API의 /admin 경로입니다. 노트북에서는 로컬 또는 Tailscale HTTPS 접속 주소 뒤에 /admin을 붙여 열고, 외부 네트워크에서는 승인된 사설 Tailscale 경로만 사용합니다. 모바일 브라우저도 같은 반응형 페이지를 사용할 수 있습니다.

1. 노트북에서 기존 License API와 PostgreSQL 서비스를 시작하고 /ready가 정상인지 확인합니다.
2. 노트북 또는 모바일 브라우저에서 관리자 /admin 화면을 열고 서버의 관리자 Bearer 토큰으로 인증합니다. 이 토큰은 고객에게 공유하지 않습니다.
3. 라이선스 기간 상품에서 7일, 30일, 90일, 365일 또는 직접 입력(custom)을 선택합니다. 고정 상품은 기간이 자동으로 맞춰지고, 서버가 코드/기간을 다시 확인합니다.
4. 최대 기기 수를 선택합니다. 고객을 연결할 경우 고객명과 이메일을 함께 입력하고 주문번호는 선택 입력합니다. 고객 정보를 연결하지 않으려면 세 필드를 모두 비워 둘 수 있습니다.
5. 라이선스 발급을 눌러 생성된 키를 즉시 복사해 안전한 채널로 해당 고객에게 전달합니다. 생성 직후 화면에 한 번만 표시되며 새로고침 후 다시 조회할 수 없습니다. 서버 DB에는 원문 키가 아닌 해시/조회 인덱스만 저장됩니다.
6. 고객은 Android 앱의 Pro/라이선스 활성화 화면에서 키를 입력합니다. 앱은 서버에 HTTPS로 연결해 해당 기기용 서명 entitlement를 확인합니다.

주의: 이 절차는 관리자 수동 발급입니다. 실제 결제 완료, 자동 이메일 전달, 자동 갱신 또는 환불 연동을 뜻하지 않습니다. 결제 공급자 검증과 webhook이 구현되기 전까지 판매 결제 상태를 관리자 발급과 별도로 확인해야 합니다.

## 3. Android 앱 고객지원 센터

설정 화면에서 다음 항목을 제공합니다.

1. FAQ: 광고 차단, VPN 연결, 앱 제외, Samsung Wallet 호환성, 필터 갱신, Pro 활성화, 기기 변경
2. 문의/의견 접수: 질문, 오류 신고, 기능 제안, 결제 문의, 라이선스 문의
3. 내 문의 답변 확인: 접수 번호와 접수 시 발급된 조회 코드를 이용한 본인 조회

문의 본문과 선택 이메일은 답변 처리를 위해 License API 서버로 전송되고 DB에 저장됩니다. 진단 정보는 별도 동의 없이 자동 첨부하지 않습니다. 사용자가 직접 진단 보고서를 복사해 문의 내용에 붙일 수는 있습니다.
현재 이메일 자동 발송은 구현되어 있지 않습니다. 입력 이메일은 관리자 문의함에 참고 연락처로 표시될 뿐이며, 고객은 접수 번호와 조회 코드로 앱에서 직접 답변을 확인해야 합니다.

접수 완료 화면은 접수 번호와 조회 코드를 한 번 표시합니다. 이 값은 닫기 전에 복사·보관해야 합니다. 조회 코드는 고객 비밀번호이므로 문의 본문, URL query, 일반 앱 로그 또는 지원 담당자 공개 문서에 포함하지 않습니다.

## 3. 서버 API 및 데이터 보호

- POST /v1/support/tickets: 문의 접수. 256비트 난수 조회 코드를 생성해 1회 반환
- POST /v1/support/tickets/lookup: 접수 번호와 조회 코드를 POST 본문으로 받아 고객 본인 문의 및 답변 반환
- GET /v1/admin/support/tickets: 관리자 Bearer 인증이 필요한 최근 300건 문의함
- POST /v1/admin/support/tickets/{uuid}/reply: 관리자 답변 및 상태(answered, in_progress, closed) 저장

DB에는 조회 코드 원문 대신 SHA-256 해시만 저장합니다. 관리자 목록 응답에서는 해시를 반환하지 않습니다. 관리자 화면은 메시지/답변 등 외부 입력을 HTML로 해석하지 않고 textContent로 표시합니다. 접수/조회/관리자 경로에는 요청 제한을 적용하고, 관리자 답변은 ticket ID를 바꿔 rate limit을 우회하지 못하도록 공통 bucket으로 처리합니다.

관리자 문의함은 /admin 화면 안에 포함되며 기존 라이선스/고객/감사기록과 동일한 관리자 인증 세션을 사용합니다. 인증 토큰은 브라우저 저장소에 영구 저장하지 않습니다.

## 4. 기존 운영 DB 반영

기존 DB에는 migrations/003_support_tickets.sql이 필요합니다. 통합 브랜치의 Apply-GuardianLicenseMigrations.ps1는 PostgreSQL 준비 확인, 외부 경로 백업, migration 002/003 적용, 테이블 존재 검사, API 이미지 재빌드와 /ready 검증을 순서대로 수행하도록 작성되었습니다.

PowerShell 7.2에서 다음 스크립트를 실행하도록 설계되어 있습니다.

    ./Apply-GuardianLicenseMigrations.ps1

실제 사용자 노트북 운영 DB에는 아직 적용됐다고 간주하지 않습니다. 실행 직전 기존 백업 유효성, 현재 컨테이너 및 데이터 경로를 확인해야 합니다. 실패하면 새 초기 DB를 만들거나 기존 DB를 삭제하지 말고 백업과 오류를 보존합니다. schema.sql에도 신규 설치용 support_tickets 정의가 포함됩니다.

## 5. 출시 전 검증 및 보류 항목

- Android FAQ/문의 폼/조회 UI: 현재 통합 브랜치에 반영, 에뮬레이터 회귀 실행 전
- 문의 API/관리자 문의함: 통합 브랜치에 반영, DB 통합 테스트 실행 전
- 실제 노트북 DB migration 및 /ready: 미검증
- 실제 Android 기기의 문의 제출/답변 조회: 미검증
- 노트북/모바일 브라우저의 관리자 반응형 화면: 미검증
- 고객 메일 알림 및 첨부 파일: 미구현
- MFA/SSO, 다중 관리자 RBAC, WAF 및 스팸 방지 추가 계층: 공개 운영 전 별도 구성 필요
- 결제 웹훅, 중복 체험판 방지, 자동 환불/차지백, Lifetime: 미구현

기능 구현, 자동화 테스트, 에뮬레이터, 실기기, 운영 환경 검증은 각각 별도로 기록합니다. 통합 브랜치에 소스가 반영되었다는 사실만으로 배포 또는 운영 준비가 완료된 것은 아닙니다.
