# Guardian 메뉴 구성도 및 반응형 설정 화면 기준

> 상태: 구현 기준 문서  
> 적용 대상: Android, Windows, 태블릿  
> 원칙: 메뉴의 명칭·계층·기능은 플랫폼 간 동일하게 유지하고, 화면 배치와 조작 방식만 화면 크기에 맞게 바꾼다.

## 2. 메인 내비게이션

메인 메뉴는 아래 5개로 고정한다. 설정 하위 메뉴나 프리미엄 기능을 메인 내비게이션에 추가하지 않는다.

| 순서 | 메뉴 | 아이콘 의미 | 기본 화면 |
|---|---|---|---|
| 1 | 홈 | 홈 | 보호 현황과 DNS 통계 |
| 2 | 보호 | 방패 | 보호 시작·중지 및 연결 상태 |
| 3 | 앱 제외 | 앱/기기 | 설치 앱과 앱별 제외 설정 |
| 4 | 활동 | 기록/차트 | DNS 요청·차단·실패 이력 |
| 5 | 설정 | 톱니 | 설정 카테고리 선택 화면 |

## 3. 설정 화면 정보 구조와 동작

설정은 하나의 긴 목록으로 모든 옵션을 펼쳐놓지 않는다.

- 설정 진입 시 카테고리 목록을 먼저 표시한다.
- 카테고리를 선택하면 해당 카테고리의 상세 설정 화면을 표시한다.
- 상세 화면에는 카테고리 제목, 한 줄 설명, 관련 설정 그룹만 표시한다.
- 저장이 필요한 값은 명시적 저장 버튼 또는 즉시 저장 중 하나로 동작을 통일하고 저장 결과를 표시한다.
- 위험하거나 보호 연결에 영향을 주는 변경은 영향 설명과 확인 절차를 제공한다.
- 뒤로 가기는 이전 카테고리/화면으로 돌아가며 입력 중인 값은 임의로 유실하지 않는다.
- Android 앱 잠금은 사용자가 선택적으로 켜며, Android 시스템 인증 UI를 통해 기기에 이미 등록된 생체 인증 또는 기기 자격 증명을 사용한다. Guardian은 별도 지문/PIN을 저장하지 않는다. Android 10 이상에서는 지문·얼굴 또는 PIN·패턴·비밀번호 대체 인증을 허용한다.
- 라이선스·프리미엄은 설정 내부에 둔다. 독립된 메인 탭을 만들지 않는다.
- 필터링 설정과 필터 목록 관리는 설정 > 필터링 안에 둔다.

## 4. 반응형 레이아웃

### 모바일 세로
1. 하단 고정 메인 내비게이션 5개를 표시한다.
2. 설정 진입 시 카테고리 목록 화면을 표시한다.
3. 카테고리 선택 시 전체 화면 상세 페이지로 이동한다.
4. 상단에 뒤로가기와 현재 카테고리명을 표시한다.
5. 화면 하단 시스템 내비게이션 영역만큼 안전 여백을 확보한다.
6. 메뉴명은 한 줄에서 잘리지 않도록 폭을 배분하고, 작은 화면에서는 글자 크기·아이콘 간격을 함께 조정한다. 텍스트를 잘라서 해결하지 않는다.

### 태블릿 및 작은 창
1. 설정 카테고리 목록을 좌측 패널로 표시한다.
2. 선택한 카테고리의 상세 내용을 우측 패널에 표시한다.
3. 패널 폭이 부족하면 모바일 단일 화면 방식으로 전환한다.

### Windows 및 넓은 화면
1. 좌측에 설정 카테고리 내비게이션을 고정한다.
2. 우측 콘텐츠 영역에 선택한 상세 설정을 표시한다.
3. 창 크기 변경 시 콘텐츠가 겹치거나 잘리지 않도록 최소 폭과 스크롤 영역을 분리한다.
4. 메인 메뉴와 설정 하위 메뉴의 계층을 모바일과 동일하게 유지한다.

## 5. 공통 UI 및 접근성 기준

- 메뉴 이름, 순서, 아이콘 의미, 선택 상태를 모든 플랫폼에서 일치시킨다.
- 선택 메뉴는 색상만이 아니라 배경/테두리/상태 표시로도 구분한다.
- 버튼과 입력 영역은 터치·마우스 모두 조작할 수 있는 크기를 확보한다.
- 기본 선택값과 입력값은 배경과 충분한 명도 대비를 갖춰 항상 읽을 수 있어야 한다.
- 긴 설정 화면은 콘텐츠 영역만 스크롤하고 메인 내비게이션은 고정한다.
- 오류 메시지와 진단 내용은 선택·전체 복사(Ctrl+C 포함)가 가능해야 한다.
- 로딩, 빈 목록, 권한 거부, 오류, 오프라인 상태를 각각 구분해 안내한다.
- 플랫폼에서 지원하지 않는 옵션은 숨기거나 비활성화하고 지원 조건을 설명한다. 존재하지 않는 기능을 동작하는 것처럼 표시하지 않는다.

## 6. DNS 통계 표시 규칙

실시간 통계는 최소한 다음 상태를 서로 구분한다.

- 차단: 차단 규칙에 의해 응답을 차단한 요청
- 정상 전달: 업스트림 DNS 응답을 정상 수신·검증하고 클라이언트에 전달한 요청
- 실패: 시간 초과, 업스트림 연결 실패, 잘못된 응답, 전달 실패 등 실제 실패 상태

실패 숫자만 표시하지 않는다. 실패 상세에서 원인별 건수, 최근 발생 시각, 대상 업스트림, 오류 코드를 확인할 수 있어야 한다. 진단 근거가 없는 요청을 실패로 임의 집계하거나 통계를 초기화해 숨기지 않는다.

## 7. 완료 검수 기준

- [ ] Android·Windows·태블릿의 메인 메뉴가 동일한 5개 항목과 순서를 사용한다.
- [ ] 설정 하위 메뉴가 동일한 6개 항목과 순서를 사용한다.
- [ ] 설정 진입 후 카테고리 선택 → 상세 설정 표시 흐름이 동작한다.
- [ ] 모바일에서 하단 메뉴 글자와 아이콘이 잘리지 않는다.
- [ ] 태블릿·Windows에서 좌측 카테고리와 우측 상세 영역이 반응형으로 동작한다.
- [ ] 뒤로가기, 화면 회전, 창 크기 변경 후 선택 상태가 유지된다.
- [ ] Android 앱 잠금 설정 시 기존 기기 인증(생체 인증/기기 자격 증명)이 호출되고, 취소·실패 시 잠금 우회가 되지 않는다.
- [ ] 모든 설정 컨트롤이 실제 저장·적용 동작과 연결되어 있다.
- [ ] 진단·오류 메시지를 선택하고 복사할 수 있다.
- [ ] DNS 통계의 차단·정상 전달·실패 분류와 실패 원인 상세가 일치한다.
- [ ] 화면 캡처와 자동 UI 테스트로 각 플랫폼의 메뉴 표시를 검증한다.

> 주의: 이 문서는 메뉴 구조와 UX 구현 기준이다. 각 항목이 현재 코드에 구현되어 있거나 실제 기능 검증을 통과했다는 뜻은 아니다. 구현 상태와 검증 결과는 별도로 기록한다.
